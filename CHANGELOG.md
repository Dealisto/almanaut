# Changelog

All notable changes to this project are documented here. The format is based on
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project aims
to follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

From v1.0.0 onward, each tagged release also has a GitHub Release with
prebuilt binaries and checksums (generated by goreleaser); per-release commit
details are listed there.

## [Unreleased]

### Added
- Add a centralized discovery deviations page using persisted successful source
  observations, source failures, filters and fresh confirmation before updates.
- Add transactional CSV preview with patch/replace modes, expiring per-user
  confirmation tokens and rejection when reviewed inventory has changed.
- Add structured logical interfaces and IPv4/IPv6 allocations, integrated with
  inventory CRUD, IPAM, owner links, history, search and inventory exports.
- Add opt-in read-only SNMPv3/SNMPv2c and LLDP collection, persistent observations,
  reviewed physical-port imports and explicit confirmed cable connections.
- Track external backup job outcomes through an authenticated idempotent report
  API, bounded run history and expected-success interval monitoring.
- Add administrator-controlled health rules and thresholds, shared by inventory
  health reports and dashboard counts, with atomic configuration auditing.
- Protect selected host fields (`ips`, `os`, `cpu`, `ram`, `disk`) from inventory
  agent updates while retaining the observed values on the host page. Existing
  hosts remain unprotected until explicitly configured. API and CSV updates
  that omit the policy preserve it; explicit empty values clear it.
- Add live database backup and read-only verification commands, optional
  scheduled snapshots with retention, and an admin-only snapshot list that
  survives restarts. Backups include the complete SQLite database; external
  configuration and secret files remain separately managed.
- Add a bounded physical topology view with device, rack and site scopes,
  directly connected peers, accessible connection tables and SVG export.

### Changed
- Export inventory format version 4 to preserve host agent-protection policies,
  structured interfaces/IP addresses and backup interval policies;
  imports still accept versions 1 through 3. Older binaries reject the new
  format, so retain a pre-upgrade database backup for rollback.

### Fixed
- Preserve the request origin on same-origin HTTP form submissions so browser
  login works on LAN addresses, while retaining cross-origin CSRF protection
  and suppressing referrers sent to other origins.

## [1.2.0] - 2026-11-27

### Added
- Audit successful role changes and API-token creation, revocation and rotation,
  with safe metadata and no duplicate success events for ineffective requests.
- Add select-all controls and selection counts to discovery imports and field
  reviews, keeping forms independent and disabling actions with no selection.
- Persist outbound webhook deliveries with inventory mutations in SQLite.
  Resume retries after restarts with stable delivery IDs, signatures and bodies;
  show pending deliveries on the Webhooks administration page.
- Add a dependency-free Chromium regression runner covering navigation, browser
  history, deep links, bulk selection, accessible row labels and search pages.
  Run it with `node tests/browser/run.mjs`; see `docs/testing.md`.
- Paginate inventory lists and global search in the database, including Unicode
  matching, custom-field filters, stable numeric-aware sorting, and visible
  previous/next controls. Saved views open on their first page; bulk selection
  applies only to the displayed page.
- Add optional API-token expiry, coarse last-used timestamps, and guided
  rotation: prepare a replacement, verify its use, then retire the old token.
  Existing tokens keep their previous no-expiry behavior.
- Persist liveness transition notifications atomically with observations and
  retry them fairly after delivery failure or restart, preserving per-entity
  order. Notification delivery runs alongside probes instead of delaying them.
- Add a **Sign in with SSO** button when reverse-proxy authentication is
  configured, with a dedicated `/login/sso` entry point, safe return paths and
  an accessible fallback to password login when SSO cannot complete.
- Discover XCP-ng hosts and VMs through Xen Orchestra, preview and import
  selected records, and optionally link VMs to their hosts. Scheduled discovery
  records findings for manual review without overwriting inventory.
- Document and test Podman discovery through its Docker-compatible socket,
  including rootless setup and Podman Compose project labels.
- Configure multiple Docker/Podman engines, Proxmox clusters and Xen Orchestra
  instances through `ALMANAUT_DISCOVERY_SOURCES_FILE`, each with a stable source
  key, its own review page, and an optional discovery interval.
- Persist source/resource identities when importing or confirming a matching
  manual record. Source and inventory renames retain the association without
  overwriting manual fields; distinct identities remain separate across sources.
- Show import results with added, already-present, skipped and host-link counts.
- Review and explicitly replace a recreated resource's source identity while
  preserving its existing inventory record, manual details, and relationships.
  Fresh scans and transactional checks reject ambiguous or stale confirmations.
- Show source health, last successful resource counts, estimated schedules, and
  admin-only controls for existing discovery jobs directly on Discover.
- Filter discovery results by import status or text and open matched inventory
  records directly. Import selections contain only the visible rows.
- Review observed field differences before accepting selected updates. Missing
  resources are labelled not observed, with their last successful observation
  when available; discovery never automatically removes inventory records.

### Changed
- Reuse webhook admission accounting when replacing a custom host type across
  multiple hosts, avoiding repeated backlog scans within the same transaction.
- Update `golang.org/x/crypto` to v0.59.0 and its required `golang.org/x/sys`
  dependency to v0.50.0, removing module-level vulnerability warnings for
  unused SSH and OpenPGP packages.
- Build entity selector options from IDs and labels only, preserving the
  catalog's ordering and composite names in a read-only snapshot without loading
  full entities and their display decorations.
- Resolve detail-page relationship labels only for the connected records.
  Relationships and their labels share a read-only snapshot while unrelated
  inventory is left unloaded.
- Resolve tag drilldown labels only for the referenced records, using batched
  queries and a consistent read-only snapshot instead of loading all inventory.
- Compare bounded decimal values directly when they underflow to zero in
  float64, avoiding large temporary binary mantissas during inventory sorting.
  Preserve signed-zero equality and the existing fallback for extreme exponents
  and hexadecimal notation.
- Resolve activity-feed links with bounded, ID-only queries for referenced
  records instead of loading and decorating the entire inventory.
- Reuse webhook admission accounting across bulk edits, bulk deletions and
  generated ports, including indirect changes, within each write transaction.
  Discovery imports use the same transaction scope while preserving independent
  source identities and atomic bindings, relationships and delivery writes.
- Reuse webhook endpoint configuration and admission counters across CSV rows
  within their inventory transaction. Keep legacy dispatchers compatible and
  preserve atomic rollback when the delivery count or byte limit is reached.
- Read only the selected owner's existing port names during bulk port
  generation, avoiding full inventory loading and label decoration.
- Parse CSV imports one record at a time, reusing the field slice and keeping
  only the validated write plan instead of a second complete list of CSV rows.
  Release that plan when a row is invalid while preserving error diagnostics
  and all-or-nothing writes.
- Read webhook backlog capacity once per staged batch instead of rescanning
  the queue for every delivery, while retaining transactional count/byte limits
  and inserting bodies individually.
- Skip reserved IPAM intervals during next-free searches and reuse parsed
  reservation ranges for local counts and global exclusions, reducing time and
  allocations for large reserved subnets and reservation inventories.
- Paginate `/api/relationships` in the database with the same default of 50,
  maximum of 100, and navigation headers as entity collections. Clients needing
  every relationship must follow the `Link` header; array response shape stays
  unchanged. Count and page use one read-only snapshot.
- Start notification channels independently and resume interrupted expiry passes
  fairly so a slow receiver or early item cannot starve later alerts.
- Index IPAM network prefixes for address attribution, preserving longest-prefix
  matching, first-network tie breaking and IPv4-mapped IPv6 behavior without
  scanning every network for each host address.
- Bound persisted webhook requests to 10,000 deliveries and 64 MiB. Saturation
  rolls back inventory changes with a retryable HTTP 503 instead of losing
  events. Editing, disabling or deleting an endpoint cancels queued deliveries.
- **API pagination:** inventory collection and search endpoints now default to
  50 records and accept `page` / `per_page` (maximum 100). JSON arrays retain
  their shape; clients needing every result must follow the `Link` header.
  `X-Total-Count`, `X-Page`, and `X-Per-Page` make the response bounds explicit.
- Bound concurrent password work across login and account provisioning; excess
  requests receive HTTP 503 with `Retry-After` without an unbounded wait queue.
- Schedule each recurring pass after the previous pass finishes plus its
  interval. Manual runs restart this delay, matching the displayed next run.
- Label container discovery as Docker / Podman while preserving existing
  single-source environment settings and default review routes. New scheduled
  engine runs use `type:id` source keys for independent history and comparisons.
- Return engine import summaries directly with HTTP 200 instead of redirecting
  to the inventory list. Repeated imports recognize existing associations.
- Write YAML export format 3 with discovery associations. Formats 1 and 2 remain
  importable; invalid associations reject the complete import. Credentials and
  source configuration are excluded. Older binaries reject format 3, so rollback
  requires a pre-upgrade database backup.

### Security
- Make 2FA enrollment confirmation atomic; repeated confirmation cannot expose
  an active secret or replace recovery codes, and setup cannot disable an
  already active factor.
- Complete second-factor login in one transaction so database failures do not
  consume a recovery code or challenge without creating a session. Concurrent
  requests cannot use one challenge to create multiple sessions.
- Revoke pending second-factor challenges when changing or resetting a user's
  password. The startup administrator reset also revokes sessions atomically
  with the password and role changes, preserving enrolled 2FA and API tokens.
- Prevent caching of dynamic pages and API responses, including tokens, TOTP
  secrets and recovery codes, while keeping static asset revalidation.
- Move destructive-action confirmations into the external script and remove
  inline script permission from the Content Security Policy.
- Keep Proxmox response bodies and reflected authentication secrets out of
  user-visible errors and logs.

## [1.1.1]

### Security
- Limit login request bodies and identity/password lengths before password
  verification, throttling and auditing. Bound stored authentication audit
  fields so oversized requests cannot inflate individual audit records.
- Reject URL control characters in login and theme return paths, preventing
  tab-obfuscated redirects to external sites.
- Bound rack placement values and rendering work, including existing records
  with extreme dimensions or integer overflow. Invalid placements remain
  visible as warnings without unbounded rendering loops.

### Fixed
- Enforce authentication audit retention on the first request and at most once
  per hour afterward, including SSO, API, 2FA and health requests. A retention
  value of zero still keeps history indefinitely.
- Prune discovery history atomically when recording a run. Keep the latest
  50 runs, plus each source's latest run and last successful comparison
  baseline, so long outages do not make known findings appear new again.

## [1.1.0]

### Added
- Manage host types from **Settings & data → Host types**: add custom types,
  rename display labels, and delete unused types. Deleting a type still in
  use requires a replacement; reassignment preserves host details and custom
  fields, records host history, and dispatches update webhooks atomically.
  Addresses #141.
- `GET /api/host-types` lists stable type names and display labels. Custom
  types are available in host forms, the host API, CSV imports, and network
  discovery imports. Search matches both the type name and its label.

### Changed
- Store the host type catalog in SQLite. The built-in names `physical`, `vm`,
  `lxc`, and `vps` remain stable and cannot be deleted; their labels can be
  renamed without disrupting Proxmox discovery or agent reports. Existing
  host assignments are preserved during migration, and agent updates retain
  manually selected custom types.
- YAML exports now use format version 2 and include the host type catalog.
  Version 1 exports remain importable and restore the original built-in
  catalog when no types are supplied. Invalid catalogs are rejected before
  replacing any inventory. Older releases reject version 2 exports; use a
  pre-upgrade database backup when rolling back to an older release.

### Security
- Build with Go 1.26.11 or newer, including the container image, to fix
  GO-2026-6859 in the standard library's HTTP server and pass the CI
  vulnerability scan.

## [1.0.2]

### Added
- NIC and port entities, for recording which switch port each machine is
  cabled to. A port belongs to a host or a hardware item (a switch, a
  router). A host's port can belong to one of that host's NICs (onboard or
  expansion card). Connecting two ports shows the link on both ports and on
  both owners' detail pages. A port has at most one link, so connecting to a
  port that is already cabled elsewhere is refused. The new-port page can
  generate "Port 1" to "Port N" for an owner in one step, skipping names that
  already exist. Deleting a NIC keeps its ports and only clears their NIC.
  Contributed by @tagawa0525 in #127.
- Free-text search within each inventory list, combined with existing tag
  filters, sorting, and saved views.

### Changed
- Refresh the light and dark interfaces with grouped navigation, a responsive
  dashboard, actual liveness results, service cards, and port connections.
- Organize record details into Overview, Connections, and Activity & files
  tabs, while keeping every section available without JavaScript.
- Make settings and account pages easier to scan, with clearer import/export,
  user management, API token, two-factor authentication, and webhook forms.
- Improve contrast, keyboard navigation, mobile menu focus, scrolling tables,
  form labels, validation feedback, and clipboard fallbacks. Refresh the
  README screenshots to match the implemented interface.

### Security
- Build with Go 1.26.10 or newer, including the container image, to pick up
  the standard-library security fixes missing from Go 1.26.8 and clear the
  vulnerability check in CI.
- Changing a password now ends the user's other sessions, and an admin
  password reset or 2FA reset ends all of that user's sessions. Previously a
  stolen session cookie stayed valid for its full 30 days, and the 2FA reset
  only claimed to revoke sessions.
- A TOTP code is now accepted only once. It could previously be replayed for
  about 90 seconds, to log in again or to turn 2FA off.
- The last admin can no longer be demoted or deleted, and
  `ALMANAUT_RESET_ADMIN` now gives the reset account the admin role back, so
  user management can no longer be lost without a way back.
- Notification and webhook URLs are no longer written to the log. A failed
  request's error used to include the full URL, which logged the Discord
  webhook token, the ntfy topic, or a webhook endpoint's embedded token on
  every DNS failure or timeout. Logs now show only the scheme and host.

### Fixed
- Failed YAML restores retain the CSV record-type choices and the restore
  form. Invalid two-factor codes retain an accessible form for retrying.
- Theme changes preserve the current page and record tab; journal and
  attachment actions return to Activity & files.
- Deleting, or resetting the 2FA of, a user that does not exist now returns
  404 instead of silently redirecting (and, for the 2FA reset, writing an audit
  event with no username).
- A YAML import no longer leaves per-entity state describing whatever entity
  used to have an id. Liveness status, certificate probe results and
  notification state are cleared and rebuilt by the background jobs, and
  attachments of entities the file no longer contains are deleted.
  Attachments of entities still present follow their id, and history is kept.
- Adding a tag, relationship, journal entry or attachment now checks, in the
  same transaction, that the entity exists. Before, one posted for a deleted
  entity (or an id not used yet) was stored as an invisible orphan, or
  inherited by the entity that later got that id.
- Import skips relationships, tags, journal entries and custom-field values
  that point at entities missing from the file, normalises tag names, and
  refuses a file from a newer snapshot format.
- `docs/export-import.md` no longer calls the YAML export a complete backup,
  and lists what it leaves out.
- Liveness checks now dial up to 16 targets at once. Checked one at a time, a
  dozen unreachable addresses used up the whole pass, so every target after
  them stopped being checked and kept a stale status.
- A panic in a background job, the Uptime Kuma sync, a liveness check or a
  webhook delivery is now logged and recorded as a failed pass, instead of
  crashing the server.
- Shutdown now waits for background jobs and queued webhook deliveries before
  closing the database, within one 9-second deadline (inside Docker's default
  10-second stop grace period). Before, a pass could be cut off between sending
  a notification and recording it, so the notification was sent again after a
  restart.

  discovery runs in a new `docs/background-jobs.md`.

### Changed
- Documentation is now split by topic under `docs/` (installation,
  configuration, authentication, inventory model, discovery, agent,
  integrations, export/import, API, monitoring), with the README reduced to a
  landing page that links to them. Anchors on the old single-page README
  (e.g. `#inventory-agent`) no longer resolve; use the corresponding page in
  `docs/`. The agent release archive now also ships `agent.md`.

### Fixed
- The security model no longer states that two-factor authentication is
  unavailable — TOTP 2FA shipped in 1.0.0.
- Documented six environment variables the binary already read but the
  configuration table omitted: `ALMANAUT_PROXY_AUTH_HEADER`,
  `ALMANAUT_PROXY_AUTH_ALLOWLIST`, `ALMANAUT_PROXY_AUTH_AUTOPROVISION`,
  `ALMANAUT_PROXY_AUTH_DEFAULT_ROLE`, `ALMANAUT_AUTH_AUDIT_RETENTION_DAYS`,
  and `ALMANAUT_STALE_AFTER_DAYS`.
- Write transactions now begin `BEGIN IMMEDIATE`, taking SQLite's write lock up
  front instead of trying to upgrade to it after a read. A transaction that
  read before it wrote could previously fail outright the moment another
  connection committed — `busy_timeout` never covered that case, because SQLite
  refuses the upgrade without invoking the busy handler — which surfaced as a
  `500` on concurrent writes, most visibly on `POST /api/agent/report` when two
  machines reported under the same agent id. Contenders now wait for the lock
  instead. Fixes #130.

  The trade-off, for anyone driving concurrent writes through the API: a write
  transaction now serializes other writers for its whole body rather than from
  its first write, so parallel writes queue where they previously overlapped.
  Reads are unaffected — WAL lets them run alongside the writer — and a whole
  inventory export, which only reads, explicitly opts out of the lock.

### Security
- CI and the published container image build on Go 1.26.8, clearing six
  standard-library advisories reported against 1.26.5 (GO-2026-6218,
  GO-2026-6091, GO-2026-6090, GO-2026-6089, GO-2026-5972, GO-2026-5026). The
  toolchain is pinned in both `go.mod` and the `Dockerfile`.

## [1.0.0]

First stable release. almanaut is a single-binary homelab CMDB: SQLite storage,
server-side-rendered UI, no client-side JS framework. This entry summarizes the
capabilities that make up v1.0.

### Core inventory
- Catalog-driven entities with full CRUD, tags, relationships, per-entity change
  history and journal, and attachments: hosts, services, networks, domains,
  certificates, backups, hardware, subscriptions, accounts, sites, locations,
  racks, contacts, VLANs, and IP reservations.
- Global search, impact analysis, and dependency graph across all entities.
- Whole-inventory YAML export/import and additive per-type CSV import.

### Infrastructure modelling
- Physical hierarchy (Site → Location → Rack) with U-based rack elevation.
- First-class IPAM: VLANs and IP ranges, network occupancy, conflict/overlap
  detection, and next-free-address suggestions.
- User-defined custom fields on any entity type, integrated into forms, global
  search, the JSON API, and YAML export.

### Automation & live data
- Internal job scheduler for background tasks.
- Native TCP liveness checks, TLS certificate expiry probing, and scheduled
  auto-discovery from Docker, Proxmox VE, and network subnet scans.

### Data quality
- Inventory health report with fixed audit rules, IPAM conflict detection, and
  stale-entity detection.

### Interfaces & integrations
- Read-write JSON API gated by per-user scoped API tokens, with a generated
  [OpenAPI 3](https://spec.openapis.org/oas/v3.0.3) document (`/api/openapi.json`)
  and a built-in reference page (`/api/docs`).
- Prometheus `/metrics` endpoint.
- Outbound webhooks, Discord and ntfy expiry notifications, and Uptime Kuma sync.

### Security
- Login required for the whole UI and API; role-based access control
  (admin / editor / viewer).
- TOTP two-factor authentication with recovery codes.
- Reverse-proxy header authentication (SSO) with an IP allowlist.
- Authentication audit log.

### Productivity & UX
- List filtering, sorting, bulk actions, and saved views.
- Instrument-panel UI with system/light/dark themes.

### Operations & release
- Distroless, non-root, multi-arch (`linux/amd64`, `linux/arm64`) container
  image with a built-in `HEALTHCHECK`.
- `/healthz` liveness probe reports the running version; `/version` exposes it
  as JSON.
- Versioned releases: pushing a `v*` tag publishes prebuilt binaries with
  checksums (goreleaser) and container tags `:X.Y.Z`, `:X.Y`, and `:latest`.
